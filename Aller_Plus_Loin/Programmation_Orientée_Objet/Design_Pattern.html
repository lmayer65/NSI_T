🐍 Design patterns et héritage en Python

Un design pattern est une solution générale et réutilisable à un problème classique de conception logicielle.

Les exemples suivants montrent comment l'héritage et le polymorphisme peuvent être utilisés pour organiser un programme Python.

1. Le pattern Composite

1.1. Principe

Le pattern Composite permet de manipuler de la même manière un objet simple et un ensemble d'objets.

Il est particulièrement adapté aux structures en arbre, par exemple un système de fichiers composé de fichiers et de dossiers.

class Element:
    def __init__(self, nom):
        self.nom = nom

    def afficher(self):
        pass

La classe mère possède un constructeur qui initialise l'attribut commun nom.

Les classes filles utilisent ensuite super().__init__(nom) pour appeler ce constructeur.

Deux classes filles héritent de Element.

class Fichier(Element):
    def __init__(self, nom):
        super().__init__(nom)

    def afficher(self):
        print("Fichier :", self.nom)


class Dossier(Element):
    def __init__(self, nom):
        super().__init__(nom)
        self.contenu = []

    def ajouter(self, element):
        self.contenu.append(element)

    def afficher(self):
        print("Dossier :", self.nom)

        for element in self.contenu:
            element.afficher()

Utilisation :

f1 = Fichier("cours.pdf")
f2 = Fichier("programme.py")

dossier = Dossier("NSI")
dossier.ajouter(f1)
dossier.ajouter(f2)

dossier.afficher()
Dossier : NSI Fichier : cours.pdf Fichier : programme.py

Un dossier peut lui-même contenir un autre dossier :

images = Dossier("Images")
images.ajouter(Fichier("schema.png"))

dossier.ajouter(images)
dossier.afficher()

Le même appel element.afficher() fonctionne pour un fichier comme pour un dossier : c'est du polymorphisme.

2. Le pattern Strategy

2.1. Principe

Le pattern Strategy permet de séparer un comportement de la classe principale afin de pouvoir le remplacer facilement.

class StrategieAttaque:
    def attaquer(self):
        pass


class AttaqueEpee(StrategieAttaque):
    def attaquer(self):
        print("Frappe avec une épée")


class AttaqueArc(StrategieAttaque):
    def attaquer(self):
        print("Tire une flèche")
class Personnage:
    def __init__(self, nom, strategie):
        self.nom = nom
        self.strategie = strategie

    def attaquer(self):
        print(self.nom, ":", end=" ")
        self.strategie.attaquer()
guerrier = Personnage("Conan", AttaqueEpee())
archer = Personnage("Legolas", AttaqueArc())

guerrier.attaquer()
archer.attaquer()
Conan : Frappe avec une épée Legolas : Tire une flèche

On peut même changer de stratégie pendant l'exécution :

guerrier.strategie = AttaqueArc()
guerrier.attaquer()

3. Le pattern Template Method

3.1. Principe

Le pattern Template Method définit les grandes étapes d'un algorithme dans la classe mère, puis laisse les classes filles redéfinir certaines étapes.

class Personnage:
    def jouer_tour(self):
        self.se_deplacer()
        self.attaquer()

    def se_deplacer(self):
        print("Le personnage se déplace")

    def attaquer(self):
        pass
class Guerrier(Personnage):
    def attaquer(self):
        print("Le guerrier frappe avec son épée")


class Archer(Personnage):
    def attaquer(self):
        print("L'archer tire une flèche")
g = Guerrier()
a = Archer()

g.jouer_tour()
a.jouer_tour()

La structure générale de l'action reste la même, mais chaque classe fille peut définir sa propre attaque.

4. Le pattern Factory Method

4.1. Principe

Une fabrique permet de centraliser la création d'objets.

class Personnage:
    def attaquer(self):
        pass


class Guerrier(Personnage):
    def attaquer(self):
        print("Frappe avec une épée")


class Archer(Personnage):
    def attaquer(self):
        print("Tire une flèche")
def creer_personnage(type_personnage):
    if type_personnage == "guerrier":
        return Guerrier()

    if type_personnage == "archer":
        return Archer()
p = creer_personnage("archer")
p.attaquer()
Tire une flèche
Résumé
  • Composite : manipuler uniformément des objets simples et des groupes d'objets.
  • Strategy : remplacer facilement un comportement par un autre.
  • Template Method : fixer la structure d'un algorithme et laisser certaines étapes aux classes filles.
  • Factory Method : centraliser la création des objets.
